# SheMesh Tribe LLC — Pilot Analytics & Improvement Matrix

## Purpose

The three pilot applications are free pilot deployments. SheMesh Tribe LLC uses the pilot to learn what works, what fails, what users need and what should become part of the production product.

## Product telemetry

Measure, where appropriate and with organisational agreement:

- onboarding completion
- active users
- role activation
- dashboard usage
- workflow starts
- workflow completions
- workflow abandonment
- error events
- failed submissions
- feature adoption
- task completion
- time-to-completion
- support requests
- feedback submissions
- feature requests
- usability ratings

Avoid collecting content of sensitive records when an aggregate event is enough.

## User journey measurement

### Common journey

Invite → registration → onboarding → role assignment → first task → task completion → repeat use → feedback.

### Operational journey

Task assigned → task opened → information entered → evidence captured → submitted → approved/closed → reported.

### Feeding journey

Sponsor/resource → allocation → stock → preparation → measurement → serving → people reached → reconciliation → impact report.

## Improvement loop

Observe → measure → collect feedback → identify friction → prioritise → fix → test → compare → document → release.

## Privacy boundary

The organisation remains responsible for its operational records. SheMesh should receive only the minimum information needed for platform operation, support and agreed pilot evaluation. Where individual-level data is unnecessary, use aggregate or de-identified measurements.
